# Companion offline follow-on

This build remains an inert preview unless the existing exact trial authorization gates are satisfied. It does not prepare OS routes, start a call, listen in the background, or enroll a device. Start a fresh voice call in the same original dot conversation manually after the operator has completed the separately approved preparation. “My original call is open” is a local UX gate, not a launch adapter, identity proof or grant. The worker still checks the original one-use, mode-bound, route-bound authorization, TLS profile, Ready nonce, number match and physical mic consent.

The visible stages cover preparation, original call required/ready, pairing, physical consent, conversation, restoration, and closure. In the current firmware, the robot’s matching-number “Pair & authorize mic/speaker” confirmation grants physical consent; the physical-consent stage waits for the accepted protocol acknowledgement, not a second unimplemented button. Conversation status reports accepted session authority; it does not prove Mira identity or audible robot playback. The native path stays in Restoring after local worker cleanup until an independent verifier supplies a receipt for this exact attempt with original routes restored and owned process/USB/listener closure. The production verifier is unavailable in this offline increment: the existing separately reviewed supervisor remains responsible for live restoration. Transport-only mode can close after worker cleanup. Forced worker exit reports unconfirmed cleanup rather than assuming restoration.

Remember This Robot is a volatile preference request. It never skips number comparison or authorizes audio. Production enrollment, secure storage and revocation adapters are unavailable; no credential writer exists in this scaffold. Forget Device clears an unsaved preference; mock records require server revocation before secure-item deletion. Failed revocation retains the record; failed deletion requires cleanup. The UI must not claim revocation simply because a local item was removed.

Durable pairing is not implemented. The only existing credential store seen (Home Lab `GatewayClient`'s private `DeviceCredentialStore`, service `home-lab-device-credential`, account = gateway URL) holds a gateway device token for Home Lab API access; it has no robot binding or purpose, is not exposed for reuse, and is not robot trust. A failed review read leaves storage state unknown: the record is dropped from view, Forget Device reports unavailable rather than cleared, and no blind revoke/remove is attempted.

`RememberedDeviceEnrolling` is a source-only future adapter contract. `RememberedDeviceEnrollmentFeature.enabled` is a compile-time false gate; `enrollIfEnabled()` refuses before invoking any adapter. The inert test proves the adapter call count stays zero even when a mock is injected. No enrollment, credential or persistent trust path is active. Enabling this gate requires the approved robot proof-of-possession protocol, private Keychain service/access policy, and production revocation path described in the accompanying approval scope.

A future reviewed enrollment must bind a robot-held cryptographic public key and possession challenge to the host key and trust profile, with algorithm/version, revocation handle and secure OS item reference. Device MAC, boot nonce and comparison number are insufficient durable identity. A changed robot/host key or trust profile requires fresh interactive enrollment. Persist only the separately authorized enrollment credential in platform secure storage; never save the current ephemeral test token. Reconnect still obtains fresh per-session authority and physical mic consent. No Keychain calls, token generation/storage, autostart or always-on microphone are included here.

Next trial requires a fresh exact source/app review, coordinator admission, scoped user approval and a valid trust profile. The old profile rejects new starts after 2026-10-10 09:58:39 UTC and expires at 10:00:49 UTC; this task does not renew it.
